Add Templates and Fidelities to the BEV App

Register your own vehicle templates and model fidelities so the app can use them

Overview

The BEV App loads vehicle templates and their available component fidelities from config files in utils/APP/Config/Preset/. Four command-line functions let you author and maintain these configs without editing JSON by hand.

TermMeaning
Template A top-level vehicle .slx model containing subsystem references to components.
Component A reusable subsystem type (e.g., MotorDrive, BatteryHV) under Components/.
Fidelity A specific model variant for a component (e.g., MotorDriveGear vs MotorDriveGearTh).
ParamMap A component-level struct mapping model names to parameter files (e.g., "BatteryEq": "BatteryLumpedParams.m"). Used when the default naming convention does not apply.
Preset A config file defining which fidelities are available. Different presets can offer different choices for the same template.

All functions default to dry-run mode — preview first, then set DryRun=false to write.

File Placement

Before running the CLI, ensure your files are in the correct locations:

AssetLocationExample
Vehicle template Model/VehicleTemplate/ VehicleThreeWheel.slx
Component fidelity model Components/<Type>/Model/ Components/BatteryHV/Model/BatteryEq.slx
Parameter script Components/<Type>/Model/ Components/BatteryHV/Model/BatteryLumpedParams.m
Controller model Components/Controller/Model/ Components/Controller/Model/ControllerFRM.slx
Config output utils/APP/Config/Preset/ ThreeWheelConfig.json
Important: The CLI scans Components/*/Model/ folders to discover fidelities. Models placed elsewhere will not be found. Template .slx files must be in Model/VehicleTemplate/ for the app to list them.

Workflow at a Glance

The example below walks through building ThreeWheelConfig.json from scratch for the VehicleThreeWheel template.

StepFunctionWhat It Does
1bevRegisterTemplateScan template → create config with Components
2bevAddFidelity + ControlModelAdd Controls section (controller model + param file)
3bevAddFidelity + SystemParameterSet system-level parameter file
4bevAddFidelityAdd extra fidelity models to components
5bevAddFidelity + ParamFileLink non-convention param files via ParamMap
6bevUpdateTemplateAdd new components after modifying the template model
7bevCleanConfigRemove stale fidelities after deleting model files
—validateVehicleConfigValidate a hand-edited or imported JSON config

1. Register a Template

Use bevRegisterTemplate to scan a vehicle template .slx and create a config entry with its component structure.

Scan (Dry Run)

Preview what the CLI detects. The function loads the model, finds all subsystem reference blocks, and maps each to a Components/ folder.

bevRegisterTemplate("Model/VehicleTemplate/VehicleThreeWheel.slx")

Review the output to confirm all components and instances were detected correctly.

Write to Config

When the scan looks correct, specify ConfigFile and Description.

bevRegisterTemplate("Model/VehicleTemplate/VehicleThreeWheel.slx", ...
    Description = "Three-wheel electric vehicle", ...
    ConfigFile  = "ThreeWheelConfig.json", ...
    DryRun      = false)

This creates a config with:

  • Components — each detected component with its instance names and the referenced model
  • SystemParameter — defaults to "NA"
Note: If the template model contains a Controller subsystem reference, it will be auto-detected into a Controls section. Otherwise, add Controls separately using bevAddFidelity (see next step).
Tip: The config key is derived from the .slx filename (VehicleThreeWheel.slx → "VehicleThreeWheel"). If the key already exists, use Overwrite=true.

2. Add Controls & SystemParameter

Use bevAddFidelity with the ControlModel, ControlParamFile, and SystemParameter name-value arguments to add or update these sections.

Add Controller

If the template model does not contain a Controller subsystem reference, the Controls section is not created during registration. Use ControlModel and ControlParamFile to create it:

bevAddFidelity("ThreeWheelConfig.json", "VehicleThreeWheel", ...
    ControlModel     = "ControllerFRM", ...
    ControlParamFile = "ControllerParams", ...
    DryRun           = false)

This creates:

"Controls": {
    "Instances": ["Controller"],
    "Models": ["ControllerFRM"],
    "ParamFile": "ControllerParams"
}

To add additional controller fidelities, call again with a different ControlModel. Use MakeDefault=true to set the default.

Set SystemParameter

Registration defaults SystemParameter to "NA". To set a real system-level param script:

bevAddFidelity("ThreeWheelConfig.json", "VehicleThreeWheel", ...
    SystemParameter = "BEVThermalParams", ...
    DryRun          = false)
Tip: ControlModel, ControlParamFile, and SystemParameter can be combined in a single call, and can also be combined with component fidelity arguments in the same call.

3. Add Fidelities

After registration, the config lists only the fidelities found at scan time (one model per component). Use bevAddFidelity to add more.

Explore What Is Available

Call the function with fewer arguments to discover components and models.

% List all components in the template
bevAddFidelity("ThreeWheelConfig.json", "VehicleThreeWheel")

% List models on disk for a specific component
bevAddFidelity("ThreeWheelConfig.json", "VehicleThreeWheel", "BatteryHV")

The output marks which models are already in the config and which can be added.

Add a Model

Specify all four positional arguments to add a fidelity.

bevAddFidelity("ThreeWheelConfig.json", "VehicleThreeWheel", ...
    "BatteryHV", "BatteryLumped", DryRun = false)

bevAddFidelity("ThreeWheelConfig.json", "VehicleThreeWheel", ...
    "MotorDrive", "MotorDriveGearTh", DryRun = false)

To make a fidelity the default in the app dropdown, use MakeDefault=true — this places the model first in the Models list.

bevAddFidelity("ThreeWheelConfig.json", "VehicleThreeWheel", ...
    "Driveline", "DrivelineWithBraking", MakeDefault = true, DryRun = false)

4. Link Parameters (ParamMap)

By default, the app resolves parameter files by naming convention (<ModelName>Params.m). When this does not apply — for example, when reusing a component model with different parameters — specify ParamFile to create a ParamMap entry.

bevAddFidelity("ThreeWheelConfig.json", "VehicleThreeWheel", ...
    "BatteryHV", "BatteryEq", ...
    ParamFile = "BatteryLumpedParams.m", ...
    DryRun    = false)

This produces a ParamMap at the component level:

"BatteryHV": {
    "Instances": ["Battery"],
    "Models": ["BatteryEq"],
    "ParamMap": {
        "BatteryEq": "BatteryLumpedParams.m"
    }
}

ParamMap maps model basenames to param filenames. The Models list stays clean — no encoded names. Multiple models can each have their own param mapping:

"ParamMap": {
    "BatteryEq": "BatteryLumpedParams.m",
    "BatteryLumped": "BatteryLumpedParams.m"
}
Note: ParamMap replaces the older Selections approach for preset configs. Saved user setups (created by the app's Save Setup button) continue to use Selections for per-instance model/param tracking.

5. Validate a Pre-Existing Config

All CLI functions (bevRegisterTemplate, bevAddFidelity, bevUpdateTemplate, bevCleanConfig) validate the config internally before writing, so a separate validation step is not needed during normal authoring.

Use validateVehicleConfig to verify a JSON file that was created or edited by hand, or imported from another source.

% Validate all templates in a config
cfg = bevConfigRead("MyCustomConfig.json");
validateVehicleConfig(cfg)

% Validate a single template
validateVehicleConfig(cfg, "VehicleThreeWheel")

Checks required fields: Components, Instances, Models per component, and Controls structure (if present).

6. Add a Component

When you add a new component to a template model (for example, adding a HVAC subsystem reference to VehicleThreeWheel.slx), use bevUpdateTemplate to sync all configs that reference that template.

Modify the Template Model

Add the new subsystem reference block to your template .slx in Simulink. Make sure it points to a model under Components/.

Preview the Sync

Run a dry run to see what changed. The function finds every config file containing this template and prints a diff.

bevUpdateTemplate("Model/VehicleTemplate/VehicleThreeWheel.slx")

The output shows new components as +, removed as -, and modified instances as ~.

Apply Changes

bevUpdateTemplate("Model/VehicleTemplate/VehicleThreeWheel.slx", ...
    DryRun = false)

New components are added with the referenced model only. Existing fidelities and ParamMap entries in other components are preserved. Use bevAddFidelity afterwards to add extra fidelities for the new component.

Verify in the App

Open the BEV App, select the template, and confirm the new component dropdown appears.

7. Config Cleanup

Over time, model .slx files may be renamed or deleted from Components/*/Model/. Use bevCleanConfig to remove stale entries from a config file.

Preview Stale Entries

bevCleanConfig("ThreeWheelConfig.json")

The function checks every model in the config against what exists on disk and prints a per-template report.

Remove Stale Entries

bevCleanConfig("ThreeWheelConfig.json", DryRun = false)

Models whose .slx files are missing are removed from the Models list. ParamMap entries for removed models are cleaned automatically. If all models for a component are stale, the entire component is removed.

Multiple Presets

To offer different fidelity choices for the same template, register it into separate config files. Each file acts as a preset that appears in the app's Config dropdown.

% Standard preset — basic fidelities
bevRegisterTemplate("Model/VehicleTemplate/VehicleElectric.slx", ...
    ConfigFile = "StandardConfig.json", DryRun = false)

% Thermal preset — register, then swap in thermal fidelities
bevRegisterTemplate("Model/VehicleTemplate/VehicleElectric.slx", ...
    ConfigFile = "ThermalConfig.json", DryRun = false)

bevAddFidelity("ThermalConfig.json", "VehicleElectric", ...
    "MotorDrive", "MotorDriveGearTh", MakeDefault = true, DryRun = false)

bevAddFidelity("ThermalConfig.json", "VehicleElectric", ...
    "BatteryHV", "BatteryLumpedThermal", MakeDefault = true, DryRun = false)
